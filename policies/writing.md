# Human-facing writing

Use these ASD-STE100 clarity principles for new English prose.
Apply them to answers, documentation, code comments, PR text, review findings, messages, and emails.

- Use short, direct sentences. Use one topic per sentence.
- Use 20 words or fewer per sentence by default.
- Use active voice. Name the actor when known.
- Put one instruction in each procedure step.
- Put a necessary condition before the result or instruction.
- Use no more than six sentences per paragraph.
- Use American English spelling and simple verb forms.
- Use `start`, not `begin`.
- Use `check` as a noun, not a general verb.
- Avoid contractions, idioms, slang, and unnecessary synonyms.
- Keep necessary technical terms. Use one consistent term for each concept.
- Keep exact code, identifiers, commands, paths, URLs, error text, source quotations, and required formal wording unchanged.
- Preserve facts, units, scope, security conditions, and uncertainty.
- Report test states precisely: passed, failed, running, not run, skipped, or not applicable.
- Never describe incomplete validation as successful.
- Do a final style review before publication.
- Do not add routine confirmation questions.

Use the requested language when the user requests another language.
Keep the same clarity principles.
